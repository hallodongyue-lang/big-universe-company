# 大宇宙公司 · 地球 Online

以场景探索、角色对话和设施建设推进的网页经营小游戏。原生 HTML / CSS / JavaScript / Canvas，无后端、无依赖、无付费 API。

## 打开

直接用支持 JavaScript 的桌面浏览器打开单文件「大宇宙公司.html」。源码版打开 dist/index.html。GitHub Pages 部署：把 dist 内三个文件上传仓库根目录并启用 Pages，无需构建。手机请通过网页 URL 打开；系统文件预览不保证运行脚本。刷新会重新开始，暂无存档。

## 操作与剧情

点击带 ! 的场景标记触发角色或物品对话；点击地面让主角移动。对话选择会改变剧情、资源与经营结果。

选品大厅选择商品事业部 → 办公室领委任书 → 航海地图选择德国/巴西/印尼 → 渠道会客厅签约 → 筹备基地建设设施 → 港口处理事件 → 工地检查设备并和客户验收 → 年度营地复盘。

基地的广播站、联络站、服务中心、合规办公室分别对应推广、渠道、售后、合规投入，每次增减5万元，单项最高40万。设施货箱、旗帜、绿化随投入变化。预算不得透支，预留应急金可解锁更多事件处理方案。

港口无线电可切换三类固定事件。相同决策与情景产生相同结果。目标：模拟税后净利润为正、满意度≥65、风险≤45、回款率≥85%，且现金足够支持下一年100%规模的周转金。完成后可导出 Markdown 报告或打印 PDF。

## 模型和边界

全部市场、企业、角色和财务参数均为虚构教学设定。完整公式可在「玩法/模型」中查看。开发预算剩余不代表企业全部现金；制造成本通过产品毛利率体现，应收款不直接当作损失。以统一20%模拟所得税和按订单采购付款核算结算现金，不模拟实际税制、月度峰值、期末存货或融资。

主要参考国际营销 JD 中市场比较、渠道管理、履约回款、风险预警、经营复盘能力；不代表真实公司的经营系统，也不包含真实 AI 模型评分或内容运营效果验证。

## 验证

引擎沿用已检查的确定性模型。互动版完成 JavaScript 语法检查，以及135条商品×市场×渠道×事件路线的模拟DOM集成检查，涵盖对话、支出、场景切换、验收门槛、报告和八类场景绘制调用。该检查不等于真实浏览器或手机视觉验收；当前浏览器工具禁止读取本地 file 页面，未完成新版浏览器实机测试。

## 商品事业部

- 小商品：文具、收纳、日用百货；筹备费0万，机会额×1.10，毛利率−5个百分点，服务要求−2，合规要求−1。
- 大商品：民用工程机械、工业设备；筹备费8万，沿用市场基础参数。
- 电子与家电：电脑配件、小家电、照明；筹备费5万，机会额×1.05，毛利率+2个百分点，服务与合规要求各+1，风险+3。
- 食品与农产：茶叶、咖啡、常温包装食品；筹备费4万，机会额×0.98，毛利率−4个百分点，服务要求−1，合规要求+1，风险+5。
- 家居与建材：家具、灯饰、普通装饰材料；筹备费6万，机会额×1.02，毛利率−2个百分点，服务要求−1，风险+1。

全部参数为游戏平衡设定，不代表实际行业或国家数据。服务与合规要求限制1–5。筹备费同时计入预算和经营费用。不同事业部具有不同交付物、现场名称和服务反馈。

公司章程和商品介绍明确合法经营、产品安全、消费者权益、知识产权与伦理责任。仅开放示例合法民用品类；不开放违禁、侵权假货、剥削、伤害性、侵犯隐私或受管制交易。模拟合规投入不能替代现实交易的法律审查。

## 年度胜负、净利润与次年现金（本次更新）

结局明确显示成功/失败、赚/赔/保本，并列出全部未达标原因。未通关不自动等于破产；盈利也可能因为服务或资金条件未达标而失败。

统一初始资本100万元。商品成本、渠道佣金、开发及事件费、日常运营费均假设当年付清。日常运营费12万元/年，正税前利润按20%计模拟所得税，亏损不计税。这些数值为游戏设定，与真实税制无关。基地投入视为当年购买的市场与服务资源，不是资本化固定资产。

税后净利润=销售额−商品成本−佣金−开发及事件费−日常运营费−模拟税。
年末现金=100+实收货款−全部现金支出=100+净利润−未收应收款。
负现金结余代表尚缺资金才能付清支出，不自动创建借款。没有期初应收、存货、债务、新融资、利息或分红。未模拟坏账减值和月度资金峰值，年末充足不保证年中从未出现缺口。

下一年周转预留=(本年商品成本+佣金)×经营规模×垫付天数/365+(12+本年四项资源投入×60%×经营规模)/4。不同品类垫付天数15/45/30/20/40天，资源续用比例60%，均为教学假设。启动费用不重复计收。可切换70%、100%、130%经营规模；应收款只有实际到账后才变为可用现金。第二年为资金情景预览，尚无可玩回合。

测试：1856组有效组合，损益表、现金表与资本加利润的勾稽关系通过；另含盈利但未收款、亏损及现金缺口、刚好保本的已知数值案例。135条剧情流程仍通过模拟DOM检查。未新增真实浏览器/手机验证。

## 小猫教学版（0.4）

全部场景角色及对话头像为本项目代码绘制的小猫，老板为“猫总”。不使用现成人物、猫咪IP或图库，使用设备系统字体、不分发字体文件。具体来源和发布边界见 ASSET_PROVENANCE.md。

定位为运营和销售岗位的入门情景练习：市场比较、渠道成本、预算取舍、交付沟通、回款及次年资金规划。并非行业认证、实证预测或真实业务系统；专业培训前仍需业务专家审阅情景和参数，使用企业数据校准并安排讲评。

新增同预算5万元平移复盘，保持商品、国家、渠道与事件一致，列出模型内净利润变化、客户满意度和风险；仅比较单次可行平移方案，不能称为全局最优或真实因果效应。失败结果给出未达标条件，不以单一分数评判从业能力。

保留确定性规则、模型版本和假设说明。新增输入参数检查，拒绝负预算、非数值预算、超限或不存在的选项。财务与剧情回归检查通过；未完成本版本浏览器/真实手机视觉验证，不能把模拟DOM检查当成实机验证。

## 已验证可通关路线

五类商品均可使用：印尼 → 当地合作伙伴 → 推广10/渠道10/售后25/合规10万元 → 默认港口拥堵 → 当地备货与调配（5万）→ 检查商品、完成客户猫验收 → 年度复盘。

当前模型的小商品/大商品/电子家电/食品农产/家居建材净利润分别为20.8/15.8/22.6/7.3/19.8万元，全部满足五项通关条件。上述数值是游戏规则结果，不是现实投资预测。

游戏增加可选「通关提示」，不自动改动玩家选择。五个品类分别通过模拟DOM对话与操作流程抵达成功结算：预算合法、事件可支付、验收门槛通过、结算success为true且失败原因为空。该验证不等同于浏览器视觉验收。
